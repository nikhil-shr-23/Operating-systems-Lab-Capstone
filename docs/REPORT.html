OSRM - Operating System Resource Manager Simulator

Capstone technical report  |  Nikhil Sharma | Roll No 2401010084 | B.Tech CSE (Core), Section C

1. Problem Statement

An operating system must share a few scarce resources - the CPU, main memory, and secondary storage - among many competing processes while avoiding deadlock. Studying the policies involved in isolation (a scheduling lab here, a paging lab there) hides how they interact and makes comparison hard. OSRM is one integrated Python + Bash application that simulates the major resource-management functions behind a single menu/CLI, validates all input, logs every action, and produces comparable results (tables, CSV, charts and an auto-written analysis) from real runs.

Objectives. (1) Implement CPU scheduling, memory management, deadlock handling and storage management as reusable classes/functions. (2) Reproduce textbook results exactly (FCFS WT 17, FIFO/LRU/Optimal 15/12/9 faults, Banker's safe sequence P1,P3,P4,P0,P2, disk totals 640/236/331/382/299/322). (3) Never crash on bad input. (4) Integrate Bash tooling through subprocess. (5) Present analytical results with justified observations.

Environment: macOS, /usr/bin/python3 3.9, bash 3.2; core uses only the standard library, matplotlib is optional (ASCII charts are the fallback).

5. Module Descriptions

5.1 Scheduler (scheduler.py)

FCFS, non-preemptive SJF and Priority share one engine that picks the ready process with the minimum key (ties: arrival, then input order); SRTF advances to the next arrival or completion and re-evaluates; Round Robin uses a deque (new arrivals are queued before the pre-empted process). Idle gaps appear as IDLE segments. Metrics: completion, TAT = completion - arrival, WT = TAT - burst, RT = first start - arrival; CPU utilisation = busy / (last completion - first arrival); throughput = processes / that span; a context switch is a hand-off to a different process.

5.2 Memory (memory.py)

FIFO (circular victim pointer), LRU (last-use timestamps), Optimal (farthest next use), Clock (second chance with reference bits and a hand). Each run returns faults, hits, hit ratio and a frame-by-frame trace. frame_sweep runs 1..7 frames; find_belady detects increases. Fixed-partition allocation implements first/best/worst fit with per-partition internal fragmentation and a list of unallocated processes.

5.3 Deadlock (deadlock.py)

BankersState computes Need = Max - Allocation and runs the safety algorithm (passes over P0..Pn-1, producing a traced safe sequence). request_resources checks request ≤ need, request ≤ available, then tentatively grants, re-runs safety and rolls back if unsafe. detect_deadlock implements the detection algorithm and returns the deadlocked processes.

5.4 Storage (storage.py)

Each disk algorithm builds the list of head positions visited; total movement is the sum of absolute differences. SCAN/C-SCAN travel to the disk edge, LOOK/C-LOOK to the last request; the C-SCAN/C-LOOK return jump is counted. SimDisk keeps a bitmap and directory; create_file plans the allocation first and only then mutates, so duplicate names, invalid sizes, oversize files and insufficient (or insufficiently contiguous) space are rejected without changing the disk.

5.5 Reporting and Bash integration

reporting.py renders boxed tables, Gantt charts, CSV files, matplotlib charts (ASCII fallback) and rule-based observations computed from the results. bashtools.py runs gen_workload.sh (validates N, optional seed, reproducible), sysinfo.sh (portable via uname -s) and log_summary.sh (awk/grep) with a timeout and error mapping to BashToolError.

7. Technical Observations (auto-generated by reporting.py)

CPU scheduling

  • Lowest average waiting time: SRTF (5.50) versus RR (10.83), a 49% reduction - it always runs the job with the least remaining work and preempts on arrival, which minimises the time other jobs spend queued.
  • Best average response time: SRTF (3.67).
  • Round Robin (q=4) performed 9 context switches against 5 for FCFS; its avg TAT is 16.00 vs 14.67 for FCFS, showing the fairness/overhead trade-off.
  • FCFS shows the convoy effect: P5 waits 22 units because earlier arrivals run to completion first.
  • Priority scheduling makes P5 (priority 5) wait 22 units - low-priority work can starve; aging would be needed in a real OS.
  • The workload contains an idle gap (2 units); CPU utilisation is 93.9% for every algorithm because total work is fixed and only ordering changes.

Memory management

  • With 3 frames the ranking by page faults is Optimal=9 < LRU=12 < Clock=14 < FIFO=15. Optimal (9) is the theoretical lower bound; LRU (12) approximates it by using the past as a predictor of the future, while FIFO (15) ignores usage and evicts hot pages.
  • Clock (second chance) gave 14 faults - between FIFO and LRU - at the cost of one reference bit per frame instead of full timestamps.
  • Increasing frames reduces faults until every distinct page fits; in the sweep all algorithms converge to the same minimum (6 faults) once frames >= distinct pages.
  • Belady's anomaly reproduced: FIFO on 1 2 3 4 1 2 5 1 2 3 4 5 incurs 9 faults with 3 frames but 10 faults with 4 frames (more memory, more faults).
  • LRU and Optimal never showed the anomaly: they are stack algorithms, so the set of pages in memory with n frames is always a subset of the set with n+1 frames.
  • Fixed-partition allocation: best fit gave the best result (1 unallocated, internal fragmentation 433); first fit: 2 unallocated, frag 559; best fit: 1 unallocated, frag 433; worst fit: 2 unallocated, frag 659.

Deadlock handling

  • Initial state is SAFE with safe sequence <P1, P3, P4, P0, P2>.
  • Request: P1 request [1, 0, 2] GRANTED; safe sequence P1, P3, P4, P0, P2.
  • Request: P4 requested [3, 3, 0] but only [2, 3, 0] available -> DENIED (must wait).
  • Request: P0 request [0, 2, 0] would leave the system UNSAFE -> DENIED, state rolled back.
  • Banker's algorithm denies requests that would lead to an unsafe state, even though resources are available - avoidance trades some utilisation for a guarantee of freedom from deadlock.
  • Detection: the first scenario has no deadlock; after P2 asks for one more resource the deadlocked set is P1, P2, P3, P4. Detection must be paired with a recovery policy (kill or roll back).

Storage management

  • Disk scheduling: SSTF moves the head least (236 cylinders); FCFS is the worst (640), 171% more.
  • LOOK saves 32 cylinders over SCAN (299 vs 331) by turning at the last request instead of the disk edge; C-LOOK saves 60 over C-SCAN.
  • SSTF has low movement but can starve distant requests; C-SCAN/C-LOOK trade extra movement (the return jump is counted) for more uniform waiting time.
  • File allocation: contiguous allocation gives the cheapest access (avg 1.00 block reads) but left 3 free fragments (external fragmentation 35.0%) and rejected 2 operation(s); linked and indexed use any free block so they rejected 1 and 2.
  • Linked allocation has the worst direct-access cost (avg 6.60, worst 20 reads, since blocks are reached by following pointers); indexed costs a constant 2 reads but spends 6 extra index block(s).

10. Limitations and Future Work

  • Single-CPU, integer-time simulation; no multi-level feedback queues, no aging for Priority scheduling.
  • Disk scheduling treats all requests as present at time zero; no rotational latency model. Flat directory, no real file I/O.
  • Partition allocation is static (no compaction, no dynamic partitions); Clock uses a simple reference-bit model; overhead is counted in entries, not bytes.
  • Banker's algorithm assumes the maximum claims are known in advance; detection returns the deadlocked set but implements no recovery.
  • Future work: MLFQ, paging with a TLB model, resource-allocation-graph visualisation, real-time deadline scheduling.
