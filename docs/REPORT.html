1. Objective

The disk is the slowest part of a computer, and most of its access time is the seek: moving the read/write head to the right cylinder. A disk-scheduling algorithm chooses the order in which pending requests are served so that total head movement, and therefore waiting time, is reduced.

This project simulates six classic algorithms in Python, visualises how the head moves, compares them on a given queue and on thousands of random queues, and reports the results automatically.

2. Algorithms and conventions

AlgorithmRule
FCFSServe requests in arrival order. Fair, but ignores head position.
SSTFAlways serve the nearest request. Low movement, but distant requests can starve.
SCANSweep to the disk edge, reverse, serving requests on the way (elevator).
C-SCANSweep one way to the edge, jump to the other edge, sweep again in the same direction.
LOOKLike SCAN, but reverse at the last request instead of the disk edge.
C-LOOKLike C-SCAN, but jump back to the farthest pending request instead of the edge.

Conventions: total movement is the sum of |difference| between consecutive head positions. The C-SCAN / C-LOOK return jump is counted. A request exactly at the head belongs to the current direction.

3. Design

Pure-logic core (modules/disk.py) with each algorithm producing the list of head positions it visits; everything else is built on that path.

  • main.py / run.sh - interactive menu and sub-commands (simulate, visual, analyze, gen, demo).
  • disk.py - algorithms, metrics (total, average seek, seek time, service order), random experiment.
  • validation.py - every input is checked; problems raise a clear ValidationError, shown as Error: ... with exit code 2, never a traceback.
  • reporting.py - tables, ASCII head-movement visualiser, CSV, matplotlib charts (ASCII fallback), automatic observations.
  • logger.py - logs/osrm.log in the format time | LEVEL | module | message.
  • Bash - gen_requests.sh (seeded random workload JSON), sysinfo.sh, log_summary.sh, called from Python with subprocess and a timeout.

7. Observations

  • Head 53, disk size 200 cylinders (0..199), direction up.
  • SSTF moves the head least (236 cylinders); FCFS is the worst (640), 171% more.
  • LOOK saves 32 cylinders over SCAN (299 vs 331) by turning at the last request instead of the disk edge; C-LOOK saves 60 over C-SCAN.
  • Over random queues, SSTF has the lowest mean movement at the longest queue (80 requests): 286.2 cylinders vs 5404.1 for FCFS.

Overall: SSTF and LOOK give the lowest movement, but SSTF risks starvation; the circular variants cost more movement in exchange for more uniform waiting; FCFS does not scale.

8. Testing

32 unit tests were run (./run.sh test): result ALL PASSED. They cover the textbook totals for all six algorithms, exact head paths, service order, both directions, empty queues, boundary cylinders, duplicates, a single-cylinder disk, LOOK never worse than SCAN, reproducible random experiments, input validation, malformed JSON, CLI errors (no tracebacks), the Bash generator (same seed gives the same file), menu re-prompting and end-of-input handling.

9. Conclusion

The simulator reproduces the known textbook results, makes the behaviour of each algorithm visible, and shows the trade-off between total movement, fairness and starvation. Possible extensions: request arrival times, starvation / maximum-wait metrics, and a graphical front end.
